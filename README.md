# DeepPipe Mobile for QField — v0.5.14

This repository contains the standalone, touch-first QField implementation of
the DeepPipe workflows. It is independent from the DeepPipe web portal
repository and does not contain the portal frontend or backend.

## Deliverables

- `plugin/deeppipe-mobile/`: app-wide QField plugin source.
- `project-template/`: synthetic demo project configured for the live Prediction API.
- `docs/`: architecture, API contract, project schema, and device test matrix.
- `tests/`: pure JavaScript, source/package, and read-only live-contract checks.
- `dist/deeppipe-mobile-v0.5.14.zip`: installable plugin package.
- `dist/deeppipe-mobile-latest.zip`: stable installer URL, committed together with the matching source on `main`.
- `dist/DeepPipe_QField_API_Test_v0.5.14.zip`: optional complete debugging bundle generated by `build.sh` (not tracked).

The main Prediction interaction is:

```text
Open DeepPipe → Map inlet layer + UUID field → Select on map → Tap/Box/Visible → Done → Submit → Result layer
```

There is no inlet-list upload screen. The plugin snapshots selected point features from the configured QField inlet layer, including locally saved observations that have not yet synchronized. Version 0.5.14 works with ordinary QField projects: first open **Configuration**, choose the inlet point layer and its unique ID field, then confirm. **Pipeline Prediction** then uses that mapping directly; it does not ask for the layer again. The mapping is remembered per project on that device.

For multi-user or offline collection, use a text UUID field as the stable inlet ID. Configure its QGIS default value as `uuid('WithoutBraces')`, do not apply the default on update, and keep the value unchanged after feature creation. A separate human-readable display ID can coexist with the UUID.

Prediction defaults to `https://lab.yyworkshop.com/predapi`; a mock fallback
remains available. Live PyPASS assessment and hosted raster catalogs default to
`https://lab.yyworkshop.com`. The **Configuration** tab includes a single status
card that checks both services; users do not need to enter API origins. Prediction results are stored in one
`DeepPipe Prediction Results` layer, with Predicted and Potential drawn by green and yellow map
overlays that follow the layer's legend switch. The latest result is saved automatically in the project folder,
reloaded when the project is reopened, and replaced by the next successful prediction. The complete returned
attribute table can be opened from the plugin or its map-actions icon; tapping a row zooms to and highlights the
pipe. A separate GeoJSON copy can still be exported, and the server's complete job ZIP can be downloaded. The live Prediction
API currently has no authentication, so this release is for workflow testing
and must not be used to submit sensitive field data.

The deployed Prediction service writes only GNN-positive pipes at or above the
submitted threshold to `Pipes.geojson`. Within that set, final `class=1` pipes
are Predicted and `class=0` pipes are Potential after MST post-processing.
The plugin also supports the live PyPASS XYZ soil/service-life layers. Direct COG
selection is intentionally not exposed in the mobile workflow.

## Release history

### v0.5.14 — 2026-08-06 (changes since v0.4.0)

- Reworked the touch-first app-wide interface around **Configuration**, **Pipeline Prediction**, and **Service Life Assessment**. Configuration now stores the inlet layer and UUID field per project, so Prediction starts directly with map selection instead of asking for the layer again.
- Expanded project-specific GNN controls for maximum distance, probability threshold, neighborhood size, MST post-processing, and probability/length weighting. The mobile UI now labels probability as **GNN probability**, omits Elevation, and submits its weight as zero.
- Simplified service setup with built-in Prediction and PyPASS endpoints and one combined status card; removed user-facing API-origin fields and direct COG selection from the mobile workflow.
- Fixed **Tap**, **Box**, and **Visible** inlet selection and highlighting. The point handler is registered only during active selection and released afterward, preserving normal one-finger map panning.
- Classified threshold-qualified GNN-positive pipes after MST as **Predicted** (`class=1`, green) or **Potential** (`class=0`, yellow). Records below the submitted threshold, without a valid probability, or marked GNN-negative are excluded.
- Consolidated results into one persistent `DeepPipe Prediction Results` layer whose legend switch controls the complete green/yellow display. The latest result is saved as a project-local GeoJSON, restored when the project reopens, and replaced by each subsequent successful prediction instead of accumulating duplicate layers.
- Added a dynamic attribute table with every field returned in `Pipes.geojson`, available from both the plugin and a QField map-toolbar action. Selecting a row selects the feature, zooms to its pipe, and temporarily highlights it.
- Retained combined GeoJSON export and added download of the server's complete job ZIP.
- Improved release reliability by synchronizing plugin metadata, source, versioned installer, and `latest.zip`; the stable installer is byte-identical to the tested `v0.5.14` package and is committed with the source. GitHub Actions packaging is now manual validation rather than a dependency for installer publication.

### Earlier foundation

- **v0.4.0:** Connected Prediction and PyPASS Assessment to their live APIs, added combined result export and outcome display layers, and added hosted PyPASS XYZ raster layers.
- **v0.3.0:** Made the app-wide plugin usable with ordinary QField projects, added per-project inlet-layer/unique-ID setup and UUID guidance, and introduced bulk **Tap**, **Box**, and **Visible** map selection.
- **v0.2.0:** Published the initial standalone QField plugin with map-based inlet selection, live Prediction submission and polling, a mock assessment workflow, a demo project, documentation, and automated checks.

## Install in QField

Use the stable `dist/deeppipe-mobile-latest.zip` direct HTTPS URL. Then open
**Settings → Plugins → Install plugin from URL** in QField and enter that URL.
The URL must return the ZIP itself rather than an HTML page or sign-in screen.
The stable ZIP and the versioned ZIP are built and committed in the same release
commit, so installation does not depend on a later GitHub Actions publishing job.

For the first device test, either open `project-template/DeepPipe_Mobile_Demo.qgs`
or open an ordinary project containing a point layer with a unique string/integer ID field. Follow `docs/TESTING.md`.

## Build and test

```bash
node tests/test_logic.mjs
node tests/validate_source.mjs
node tests/test_api_contract.mjs
./build.sh
```

The pure-JS, source, demo-project/GeoJSON, live-contract, and ZIP checks do not replace a QField phone test. Follow `docs/TESTING.md` on QField 4.2.10 for Android and iOS.

## Host the installer

Use `dist/deeppipe-mobile-latest.zip` as the stable public HTTPS installer on the
deployment server. The URL must return the ZIP bytes directly (not a login or
HTML download page), preferably with `Content-Type: application/zip`. In
QField, open **Settings → Plugins → Install plugin from URL** and enter that
URL. The complete API test bundle generated by `build.sh` is for debugging and
is not the installable plugin.
